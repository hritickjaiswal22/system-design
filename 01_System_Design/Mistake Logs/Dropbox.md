# Mistake Log

## Mistake(s)

1. Listed share files in Functional Requirements but then did not solve it (stupid mistake)
2. Missed NFR of low latency (this is almost always a NFR)
3. Very poor API design endpoints (not proper at all)
4. Use of SQL instead of DynamoDB (But SQL would also work just fine)
5. How can you assure FIle Security (Completely Missing)

---

## Why it matters

1. Not completing or providing solution for Functional Requirements is a big RED FLAG either don't include it OR if included make sure it is covered
2. Low latency is a  Non-Functional Requirement for any system design always cover it
3. Focus more on entities and then design URL endpoints
4. Study DynamoDB and practice it and get accustomed to it
5. Missed Deep Dive for file security (https://www.hellointerview.com/learn/system-design/problem-breakdowns/dropbox#3-how-can-you-ensure-file-security)


---

## Correct approach

1. Completing or covering all the FRs
2. Always account for low latency in your design
3. Make endpoints on the basis of entities you have (very simple do not overthink this)
4. No hurry but study and get proficient in DynamoDB
5. Study and prepare from [hellointerview](https://www.hellointerview.com/learn/system-design/problem-breakdowns/dropbox#3-how-can-you-ensure-file-security) .
